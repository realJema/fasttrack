## Why FastTrack

Most fasting apps want an email, a subscription and a server round-trip before you can start a timer.
FastTrack is the opposite: open it, tap start, and go. It is a pure client-side companion that tracks
your fasts, shows what your body is likely doing at each stage, and keeps a running history — entirely
on your phone.

---

## Features

- **Animated progress ring** — an SVG ring that fills as the fast progresses, with milestone emoji markers around it.
- **Idle & active states** — a dashed "tap to start" ring when idle, a live counter (`H:MM:SS`), percentage and body-status card while fasting.
- **Auto-complete** — the moment the target duration is reached the fast ends itself, records the result, and stops the timer. No manual tap required.
- **Fasting plan wizard** — a 3-step flow to pick a method, a start time, and a weekly / recurring schedule.
- **Body-phase guidance** — Hydrating → Fat burning → Ketosis → Autophagy → Deep autophagy, based on elapsed time (informational only).
- **Check-in** — log how the fast feels (😎 / 🙂 / 😩) with an optional note.
- **Analytics** — total fasts, hours fasted, current streak, longest fast, a 7-day bar chart, and a recent-fasts list.
- **Quick-start checklist & beginner tips** — onboarding help that persists as you tick items off.
- **Data export & reset** — share your fasting data as JSON, or wipe everything from the device.
- **Haptic feedback** on fast start and completion.

## Tech stack

- **Expo SDK 58** with **expo-router ~58** for navigation and file-based routing.
- **React Native 0.88.1** / **React 19.3.0**.
- **TypeScript ~6** in strict mode with an `@/*` path alias.
- **react-native-svg 15.16.0** for the progress ring and milestone markers.
- **@react-native-async-storage/async-storage 2.2.0** for all persistence.
- **expo-haptics** for tactile feedback, **@expo/vector-icons** (Ionicons) for UI icons.
- **expo-linear-gradient**, **expo-splash-screen**, **expo-constants**, **expo-font**, **react-native-safe-area-context**, **react-native-screens**.

Native code is generated by Expo (Continuous Native Generation) — there are no hand-edited `ios/` or `android/` folders. Configure native behavior in `app.json`.

```bash

npx expo start
```

## Data model & persistence

All state is centralized in `FastingProvider` and mirrored to AsyncStorage through `src/storage/storage.ts`.

| AsyncStorage key | Contents |
|------------------|----------|
| `@fasting/session` | The in-progress / scheduled fast (removed when idle) |
| `@fasting/history` | Array of completed & stopped fasts |
| `@fasting/plan` | Plan wizard settings (method, start time, schedule) |
| `@fasting/checklist` | Quick-start checklist state |
| `@fasting/profile` | Display name + goal weight |

Core types (`src/types/index.ts`):

- **FastingSession** — `id`, `startAt` (may be future for a scheduled fast), `targetMs`, `method`.
- **FastRecord** — a finished session with `durationMs` and `status` (`completed` | `stopped`).
- **PlanSettings** — `startAt`, `method`, `constantly`, `daysAmount`, `week[7]` (index 0 = Monday).
- **ChecklistItem**, **CheckIn** (mood + optional note), **UserProfile**.

Storage failures are swallowed by design so a write error can never crash the running timer.

## How the timer works

`FastingProvider` derives everything from a single ticking `now` timestamp:

- `isScheduled` — session exists and `startAt > now`.
- `isActive` — session exists and its start time has passed.
- `elapsedMs` — `now - startAt` while active.
- `progress` — `elapsedMs / targetMs`, clamped to `0..1`.

A `setInterval` fires once per second while a session exists. Each tick updates `now` **and** checks
whether `now - startAt >= targetMs`; if so it calls `endFast('completed')`, which writes a `FastRecord`
to history, clears the session, and stops the interval. Ending early via the button records a `stopped`
fast instead.

The "Nk people are fasting now" figure is **generated locally** (a deterministic per-10-minute pseudo
count in `utils/time.ts`) — it is flavor, not a network stat, keeping the app fully offline.

## Design system

Tokens live in `src/constants/theme.ts` — a purple/violet accent (`#5B34E8`) on a soft lavender
background (`#F5F3FB`), with rounded cards, pill buttons, and semantic soft-tint colors for
success / warning / info states. The ring, cards, chips and sheets all read from these tokens so
the palette is easy to retune in one place.

## Privacy

FastTrack makes **zero network requests**. There is no analytics SDK, no account system, and no backend.
Your fasting history, plan and profile never leave your device. Use **Profile → Export** to back up your
data as JSON, or **Profile → Reset** to erase it.
